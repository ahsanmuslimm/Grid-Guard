Section 04
How Every Component Connects
The complete data and control flow — from a button click on the dashboard to a trace in Phoenix.
Entry Point: main.py
  • Imports observability/phoenix_setup.py FIRST — initializes tracing before anything else
  • Imports frontend/main.py:app — the FastAPI application
  • Imports simulator/scada_simulator.py:simulator — the singleton
  • Registers on_telemetry_tick() callback on simulator
  • Callback calls tools/scada_reader.py:set_telemetry() → feeds agents
  • Callback calls frontend/state.py:push_threat_event() → feeds dashboard
  • Starts uvicorn on port 8080
Attack Injection Flow
  • User clicks button → POST /api/inject-attack/ransomware
  • frontend/main.py calls simulator.inject_attack("ransomware")
  • Simulator returns target_node, sets _active_attack
  • Adds _run_pipeline_background() as FastAPI BackgroundTask
  • Background task calls agents/pipeline_runner.py:run_pipeline_for_attack()
  • Simulator's next 2s tick generates attack telemetry → set_telemetry()
  • Agent pipeline reads telemetry via tools/scada_reader.py
Agent Pipeline Flow
  • pipeline_runner.py creates ADK session + Runner
  • Sends mission prompt to gridguard_pipeline (SequentialAgent)
  • detection_agent → calls 4 tools in scada_reader.py → writes session.state["detection_result"]
  • investigation_agent → reads {detection_result} → calls mitre_lookup + cve_lookup → writes session.state["investigation_result"]
  • response_agent → reads both results → calls request_human_approval if CRITICAL → calls execute_playbook → calls generate_incident_report
  • Each agent step logged to frontend/state.py:add_timeline_event()
  • Every tool call traced to Arize Phoenix via OTel spans
Human Approval Gate Flow
  • response_agent calls tools/playbook_executor.py:request_human_approval()
  • playbook_executor calls frontend/state.py:push_approval_request()
  • Approval payload added to _pending_approvals dict
  • WebSocket broadcasts include pending_approvals → dashboard renders modal
  • Operator clicks Approve → POST /api/approve/{incident_id}
  • frontend/main.py calls frontend/state.py:set_approval_result()
  • playbook_executor polls get_approval_result() → gets "approved" → continues
WebSocket Dashboard Flow
  • frontend/main.py:/ws/threats — connected to all browser clients
  • Every 2 seconds: calls frontend/state.py:get_dashboard_snapshot()
  • Snapshot includes: node_states, recent_threats, timeline, pending_approvals, active_incidents
  • frontend/static/app.js receives JSON → updates all UI panels in real time
  • Node states from simulator.get_node_states() → colors grid nodes red/green
  • Timeline from add_timeline_event() → each agent action visible
  • Phoenix stats from observability/evaluators.py:get_phoenix_stats() → observability panel
Arize Phoenix Observability Flow
  • observability/phoenix_setup.py registers OTel tracer provider globally
  • Auto-instruments all VertexAI + GoogleGenAI calls (automatic — no manual wrapping needed)
  • Every tool function has tracer.start_as_current_span() with custom attributes
  • pipeline_runner.py wraps entire pipeline in gridguard.full_pipeline span
  • All spans exported to https://app.phoenix.arize.com/v1/traces
  • evaluators.py runs post-incident hallucination + relevance evaluation
  • Phoenix stats polled by GET /api/phoenix-stats for dashboard panel
